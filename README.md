# 回响 · 微信接待助手

一个运行在 macOS 上的本地桌面预览版，沿用蓝白色工作台设计。通过屏幕截图、Apple Vision OCR 和系统键鼠事件处理**一段明确指定的微信会话**。无需注册企业微信，也不读取微信数据库、不要求微信密码、不修改微信客户端。

## 当前可用

- 选择本机微信窗口，预览并标记标题、消息区、输入框和输入位置。
- 保存业务介绍、常见问答、关键词、启用状态和逐条自动回复授权。
- 读取可见会话，按资料生成草稿，编辑后确认发送。
- 可选兼容 OpenAI 的模型接口。模型生成内容始终由人确认。
- 自动模式只对**新出现的客户消息**发送明确授权的匹配问答。未命中、歧义和需确认内容留给人工。
- 会话名称不匹配、窗口尺寸变化、已有输入草稿、人工操作、锁屏、休眠等情况下停止或等待。
- 发送前多次核对标题与消息，输入后读回核对文字，再执行 Enter。发送不明确时记入本地账本并停止，不自动重试。
- 本地记录、加密密钥存储，以及独立的操作演示。

## 使用

构建产物为 `dist/回响.app`，可直接打开；建议移动到“应用程序”后再授权，避免移动路径影响系统权限。

1. 在电脑微信里打开要接待的聊天，保持窗口展开。微信发送快捷键设为 **Enter**。
2. 在“渠道连接”里按需开启屏幕录制和辅助功能。系统可能显示“回响”或“HuixiangBridge”。授权后若状态未更新，重新打开软件。
3. 查找微信窗口，填写与聊天顶部**完全一致**的会话名称。
4. 预览并标记四处位置。标题框只包含名称；消息区不含联系人列表；输入框不含工具栏或发送按钮；输入位置位于文本空白区。保存连接。
5. 添加真实业务问答。默认不允许自动发送；仅对确定适用的答案勾选授权。
6. 回到工作台，读取并核对识别结果，生成草稿，先确认一条回复。真实微信收发仍需要用户授权后的实测。
7. 熟悉后在“回复规则”切换自动模式，再开始接待。**开始时不补回旧消息**，只等待后续新增消息。

按 **⌘ ⇧ .** 可紧急暂停。关闭窗口也会暂停。电脑需保持唤醒、解锁，不能把它当作无人值守服务器。

## 模型设置

服务地址填写到接口基础路径（例如 `https://你的模型服务/v1`），程序追加 `/chat/completions`。支持 HTTPS；HTTP 仅支持 `localhost`、`127.0.0.1` 和 `::1`。不内置服务商账号或密钥。

点击“生成草稿”且本地问答未命中时，才把**当前可见聊天文字、业务介绍与启用问答**发送给用户配置的模型。截图不上传。自动接待不会调用模型。测试连接只发送固定的“连接成功”请求。

密钥通过 Electron safeStorage 使用 macOS 钥匙串加密后保存；系统加密不可用时只保存在进程内存，到退出失效。请勿把数据目录、密钥或客户会话提交到代码仓库。

## 开发与验证

要求：Apple Silicon Mac、macOS 14+、Node.js 22+、Xcode Command Line Tools。

```sh
npm install
npm run build:native
npm test
npm run check
npm start
npm run build
```

`npm run build` 生成应用包；构建脚本不会覆盖已有的 `dist/回响.app`。打包程序会包含 Electron 与 Chromium 许可证。

自动测试使用合成 OCR 与内存桥接，不操作真实微信、不发送消息。原生组件可通过 `native/bin/HuixiangBridge self-test </dev/null` 运行纯数据自检。

## 本版边界

这是为当前 Mac 构建的预览版，应用包仅有本机临时签名，尚未经过 Apple 开发者签名、公证或真实账号的连续运行验收。OCR 受微信版本、主题、窗口布局和字号影响；识别不确定时拒绝自动发送。窗口调整后需要重新标记。不同客户重名、图片、语音、文件、撤回、长聊天滚动、多账号、多窗口并发、自动切换客户、WhatsApp、Telegram、Windows 版和完整客户管理均不在本版范围。

聊天对象通过窗口及可见名称验证，无法获得微信内部唯一联系人 ID；请只选择身份明确的工作会话。屏幕上的原始消息没有可靠的平台消息 ID，本地指纹账本是防重的补充措施，不能保证所有界面变化情况下的精确一次发送。

工作空间存放在系统应用数据目录的 `workspace/workspace.json`；通过左下角“本地工作空间”打开。默认仅记录操作摘要，不保存截图与客户聊天历史；常见问答、业务介绍和不可逆消息指纹保存在本机。
